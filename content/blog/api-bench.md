## はじめに
Go，Python，C#，Rubyなど、現代におけるWebAPI開発において使用されている言語はさまざまです
これらのプログラミング言語が採用される理由はプロジェクトによってさまざまかと思いますが、実際にこれらの言語で同じAPIを作成した場合にどれほどパフォーマンス面で差ができるのでしょうか？
もちろん既に検証されている内容は多いでしょうが、自分なりに各種言語で比較していきたいと思います

## 前提

まず第一に、あくまでも厳密なベンチマークではないことにご了承ください

[Riot Games - Scalability and Load Testing for VALORANT](<https://www.riotgames.com/en/news/scalability-and-load-testing-valorant>)

[１億DAUの中華ゲームを支えるアーキテクチャ](<https://qiita.com/fanliang88/items/d5e0f181963e63498ac2>)

を参考に、「ゲームバックエンドのステートレスAPI」をテーマに検証を行います（WebAPIで十分な気がしますが...という体で）

サーバー側は、以下の言語で検証します。
- C#（JIT / AOT）
- Go
- Python
- Ruby
- PHP
- C++
- Rust

C# を基準に、コーディングエージェントを使って各言語版を実装しています。

条件として
・言語やハードウェア特有の最適化は行わない
・標準的なHTTPライブラリを使用
・データベースは使わない
・一定スペック（2コア 4GB RAM）のDockerコンテナ
・スケールはしない
をつけ、できるだけ言語そのもののポテンシャルを検証したいと思います

また、クライアントはC#で実装し、こちらはk8sによるスケールで限界まで負荷をかけます

検証環境の都合上、実際に起こるであろうネットワークのオーバーヘッドは再現しません
